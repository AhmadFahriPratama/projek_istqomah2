HALAMAN 2

1. Ringkasan Eksekutif & Arsitektur Offline

Istiqomah Stock adalah aplikasi mobile manajemen stok offline-first yang dirancang khusus untuk mengelola operasional gudang dan toko bertingkat 4. Sistem ini menjawab kendala sinyal internet yang tidak stabil di area gudang bawah/atas, kebutuhan audit fisik rak yang instan, serta akurasi mutasi barang antar lantai.

Pilar Utama Sistem Offline-First

  • Zero Dependency on Internet: Berjalan 100% tanpa koneksi seluler maupun Wi-Fi. Semua data diolah langsung pada CPU dan memori lokal gawai.
  • Zero Latency: Input mutasi barang, pencarian barcode, dan filter per lantai bekerja instan (< 20ms).
  • Local Backup & Export: Backup database berkala ke berkas JSON/SQLite terenkripsi di folder penyimpanan perangkat, serta ekspor laporan ke CSV & PDF.
  • Integritas Data Transaksional: Menggunakan transaksi ACID SQLite untuk mencegah data rusak saat baterai gawai mati mendadak.

4. Modul Pelacakan Stok Habis & Rekomendasi Restock

Modul ini berfungsi sebagai sentra peringatan dini untuk mencegah terjadinya kekosongan barang (stock-out). Sistem secara cerdas membedakan barang yang habis di lantai display (Lantai 1-3) namun masih tersedia di Gudang (Lantai 4), dengan barang yang memang habis total di seluruh toko.

Matriks Ambang Batas Stok (Stock Threshold Matrix)

Status Level Kondisi Kuantitas Aksi Sistem Otomatis Indikator UI
OUT OF STOCK Stok = 0 Pcs di lantai display Kirim alert kritis, buat tiket darurat penarikan barang dari Gudang Lt 4 / PO supplier. Badge Merah Kritis
LOW STOCK 0 < Stok ≤ Min Threshold Tampilkan di daftar prioritas restock harian; hitung estimasi habis (lead time). Badge Kuning Amber
HEALTHY Min < Stok ≤ Max Capacity Stok berada pada kapasitas ideal dan siap melayani transaksi pelanggan. Badge Hijau Emerald
OVERSTOCK Stok > Max Capacity Peringatan penumpukan barang pada rak display; sarankan pemindahan ke Lt 4. Badge Biru Info

6. Skema Database SQLite & Model Relasi Data

Database dirancang dengan normalisasi 3NF dan indeks teroptimasi pada kolom pencarian cepat (sku, barcode, slot_id) guna menjamin query instan di perangkat entry-level.

-- 1. TABEL LANTAI (FLOORS) CREATE TABLE floors ( id TEXT PRIMARY KEY, floor_number INTEGER UNIQUE NOT NULL, name TEXT NOT NULL, description TEXT ); -- 2. TABEL SLOT / RAK PENYIMPANAN (SLOTS) CREATE TABLE slots ( id TEXT PRIMARY KEY, floor_id TEXT NOT NULL, slot_code TEXT NOT NULL, slot_name TEXT NOT NULL, capacity_limit INTEGER DEFAULT 500, FOREIGN KEY (floor_id) REFERENCES floors(id) ); -- 3. TABEL MASTER BARANG & STOK (ITEMS) CREATE TABLE items ( id TEXT PRIMARY KEY, slot_id TEXT NOT NULL, sku TEXT UNIQUE NOT NULL, barcode TEXT, name TEXT NOT NULL, category TEXT NOT NULL, unit TEXT NOT NULL, current_stock INTEGER NOT NULL DEFAULT 0, min_stock_alert INTEGER NOT NULL DEFAULT 5, max_stock_capacity INTEGER NOT NULL DEFAULT 100, cost_price REAL DEFAULT 0, selling_price REAL DEFAULT 0, shelf_location TEXT, is_active INTEGER DEFAULT 1, updated_at DATETIME DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (slot_id) REFERENCES slots(id) ); -- 4. TABEL MUTASI TRANSAKSI STOK (STOCK_MUTATIONS) CREATE TABLE stock_mutations ( id TEXT PRIMARY KEY, item_id TEXT NOT NULL, mutation_type TEXT NOT NULL, -- 'IN_INBOUND', 'OUT_SALE', 'TRANSFER_FLOOR', 'ADJUST_OPNAME' quantity INTEGER NOT NULL, previous_stock INTEGER NOT NULL, resulting_stock INTEGER NOT NULL, source_floor_id TEXT, dest_floor_id TEXT, reference_note TEXT, created_at DATETIME DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (item_id) REFERENCES items(id) ); -- INDEKS OPTIMASI PENCARIAN OFFLINE INSTAN CREATE INDEX idx_items_slot ON items(slot_id); CREATE INDEX idx_items_sku_barcode ON items(sku, barcode); CREATE INDEX idx_mutations_item_date ON stock_mutations(item_id, created_at);

Strategi Pemulihan Data & Pencadangan Lokal (Local Resilience)

1. Write-Ahead Logging (WAL): Mode PRAGMA journal_mode=WAL; untuk kecepatan tulis tinggi tanpa mengunci proses pembacaan.
2. Auto-Snapshot Daily: Database diekspor otomatis setiap pukul 21:00 ke penyimpanan lokal gawai (folder /IstiqomahStock/Backups/).
3. Manual Export: Satu klik di menu pengaturan untuk mengekspor seluruh basis data ke berkas terkompresi (.JSON / .db).

Matriks Pengujian Integritas Offline (QA Matrix)

Skenario Uji Kritis

  • Uji coba dalam Airplane Mode (100% tanpa internet).
  • Uji coba 10.000 transaksi mutasi berturut-turut.
  • Simulasi baterai habis saat transaksi diproses.
  • Uji responsivitas buka-tutup drawer kiri atas.

Kriteria Keberhasilan

  • Tidak ada crash atau data hilang saat offline.
  • Pencarian produk dan barcode instan (< 50ms).
  • Kalkulasi stok habis akurat 100%.
  • Tampilan responsif di berbagai resolusi layar.
